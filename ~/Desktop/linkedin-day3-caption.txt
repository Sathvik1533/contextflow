Day 3: The Debugging Marathon That Taught Me More Than Code

Yesterday I shipped Observer + Guide agents. Today I tried to add one "simple" feature: user intent prompts.

It wasn't simple.

4 hours. 6 different errors. 1 lesson I'll never forget.

THE ERRORS:
→ Python 3.14 syntax errors (numbered lists in docstrings broke)
→ Observer returning invalid JSON (prompt too complex)
→ Virtual environment activation issues (pyenv conflicts)
→ Vision model analyzing wrong window (terminal instead of browser)
→ Infinite debugging loop (fix one thing, break another)

THE BREAKTHROUGH:
Vision models need SHORT prompts. I had 70 lines of instructions. The model got confused and returned malformed JSON every time.

The fix? Cut it to 30 lines. Removed examples. Removed verbose explanations. Kept only essentials.

It worked.

WHAT I LEARNED:
→ Python 3.14 is too new (use 3.11/3.12 for production)
→ Vision model prompts must be <40 lines (long prompts = confused model)
→ Test incrementally (don't add 3 features at once)
→ Document everything (created debug-log.md with every error + solution)

Debugging teaches you:
→ How systems actually work (not how you think they work)
→ How to read error messages (they're usually right)
→ How to simplify when stuck (remove complexity until it works)
→ How to document for future you (debug-log.md saved me twice)
